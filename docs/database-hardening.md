# MongoDB hardening checklist (ADR 0010, backlog B-17)

Status: **plan only. No MongoDB instance exists yet; the app runs on SQLite.** Nothing here is a security claim until Ben has run the check and recorded the output in the "Result" column. Settings and edition facts are from the assistant's general knowledge of MongoDB and were **not fetched or tested**: confirm each against the official MongoDB manual for the version you install before relying on it. Commands are shown as starting points and have **not been run**.

Edition note (verify): MongoDB Community Server lacks some features the request names. Native encryption at rest and native auditing are Enterprise features (Percona Server for MongoDB offers equivalents; MongoDB Atlas offers its own). With Community, the usual substitutes are full-disk or volume encryption for rest, and log shipping plus application-level audit records. Decide the edition first; it changes rows 4 and 5.

## Things the move changes elsewhere

- The 11 triggers and CHECK rules must be re-created as code and validators before the move, one at a time, each with a test that fails first (B-17 step 3). Until then the move is unsafe: for example the override log is currently protected from edits by a trigger.
- Transactions need a replica set, so even a single-machine deployment runs `mongod --replSet`; row 12's "listening sockets" check includes it.
- `docs/security-review.md` area 7 (the database) and the clean-machine prerequisite table must be redone at migration time.

## Not covered

Cloud-hosted MongoDB (Atlas) settings, sharding, LDAP/Kerberos, field-level encryption, and any real penetration test of a running instance.
